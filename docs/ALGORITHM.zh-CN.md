# 图表与平滑算法

[English](ALGORITHM.md) · **简体中文**

挂件拿到的是间歇更新的额度计数器，并没有官方的每秒消耗流水。**平滑是在估计已观测消耗发生的时间分布，不会提高原始额度读数的精度。**

## 几种数字分别是什么

| 显示 | 算法 | 应该怎样理解 |
| --- | --- | --- |
| 圆环 | 最新官方额度读数 | 对应周期的剩余或已用额度 |
| 顶部累计 / 累计图 | 所选范围内完整、有效采样区间的增量之和 | 已记录消耗；重置、缺口、账号切换不凭空补点数 |
| 精简模式每小时速率 | 两次相隔约一小时的实测读数之差，除以实际间隔 | 近一小时的观测均速，不是实时瞬时速度 |
| 平滑速率曲线 | 把已观测跳点分摊到有活动证据的工作时间，再平滑 | 对消耗强弱和时段分布的估计 |

近一小时均速以最新读数为终点，从连续记录中寻找相距 45–75 分钟、最接近 60 分钟的那次读数。不按比例拆分半个采样区间，也不会只因时间流逝而改变分母。读数陈旧或间隔不在 55–65 分钟内时标 `*`；连续记录不足时不显示速率。

累计线连接已知采样端点，并不代表已经知道增量在区间内发生的准确时刻。

## 平滑怎样实现

1. 按平台和额度周期分别处理。原始记账保留缺采样、真实中断、账号变化和重置。
2. 用本机任务的开始、结束事件约束工作时间。估计时先压掉已确认的空闲，让相邻工作片段能分摊整数跳点，避免碰巧跳了 1 点就把它全部塞进某个三分钟任务。
3. 在这条“活跃时间轴”上，根据相邻读数分摊增量。工作结束后的短暂上报延迟允许归回刚结束的任务，但只限第一次后续采样，并受最多十分钟采样间隔加一分钟容差约束。
4. 使用升余弦核平滑。目标跨度自适应到约 2–3 次跳点，通常至少 30 个活跃分钟，并受设置中的 60/90/120 分钟上限约束。连续估计段的边缘使用镜像，已确认部分的面积归一到观测总量。极长历史在绘制采样变稀时，有效平滑宽度可能扩大。
5. 映射回真实时间。已知开始和结束是硬边界，空闲不会被平滑填满。使用完整可用历史估计，再裁剪成 1h、5h、12h、24h、3d 或 all 视图。

只有额度计数器重置、而本机工作证据连续时，速率可以沿用两侧上下文；原始记账周期仍然分开。尚未收口的尾段会使用逐渐减弱的续估，通常总面积最多一个计数器步长，且不画到最新观测之后。重置前已经触顶的计数器有单独的连续性处理，直到新周期出现增量。任务结束后还需要一次有效后续观测来收口，不能仅凭钟表时间推断。新读数可能修正近期曲线。

如果本机活动解释不了官方增量，会回退到观测区间估计，不把网页版或其他设备的用量硬算到某个本机 chat 上。

实现见 [ActiveRateEstimator](../src/QuotaWidget.Core/ActiveRateEstimator.cs)、[RateTrend](../src/QuotaWidget.Core/RateTrend.cs)、[TrendContinuity](../src/QuotaWidget.Core/TrendContinuity.cs) 和 [RecentUsageRate](../src/QuotaWidget.Core/RecentUsageRate.cs)。

## 跟真实速率差多少

没有官方瞬时消耗真值，就不能承诺一个经过测量的“准确率百分比”。额度没有跳点时，工作可能仍在持续消耗；一次突发和一段匀速工作，也可能产生相同的采样读数。单靠平滑无法完全区分。

举例：**若计数器按 1 点量化**，仅两端读数的量化就可能给一小时均速带来约 1 点/h 的差异，十分钟窗口则约为 6 点/h。这假设量化方式一致，未包含延迟与缺数据，是量级说明，不是误差保证。Fable 折算后若按 0.5 点跳动，量化尺度相应更细。提高采样频率能减少发现变化的延迟，但不能恢复计数器没有提供的小数精度。

额度与已记录消耗看圆环和顶部累计，近期强度看一小时均速，工作强弱变化看曲线。不要把某分钟的峰值当作精确账单。本机 token 记录用于识别活动与模型，不换算成看似精确的单 chat 周额度。

## 只用 Fable 时为什么可以共线

支持的套餐会把 Fable 折合到 Claude 周额度单位。某片段的本机模型证据仅有 Fable、且计数器差异在合并量化容差内时，**速率和累计图都共用 Fable 折合线**，省略该片段重复的 Claude 描线；累计没有新增消耗的平台段也可延续这一显示。

混用模型、未知模型、缺失覆盖、重置缺口或无法解释的额度差异仍保留两线。手动隐藏 Fable 后，会恢复 Claude 线。顶部累计和存储记录始终各自保留，所以线重合时，顶部点数仍可能不同。累计视图中的共线表示该范围的 Fable 累计，不是修正后的 Claude 账单。
