# 图表与平滑算法

[English](ALGORITHM.md) · **简体中文**

挂件拿到的是间歇更新的额度计数器，并没有官方的每秒消耗流水。**平滑是在估计已观测消耗发生的时间分布，不会提高原始额度读数的精度。**

## 几种数字分别是什么

| 显示 | 算法 | 应该怎样理解 |
| --- | --- | --- |
| 圆环 | 最新官方额度读数 | 对应周期的剩余或已用额度 |
| 顶部累计 / 累计图 | 所选范围内完整、有效采样区间的增量之和 | 已记录消耗；重置、缺口、账号切换不凭空补点数 |
| 精简模式每小时速率 | 两次相隔约一小时的实测读数之差，除以实际间隔 | 近一小时的观测均速，不是实时瞬时速度 |
| 平滑速率曲线 | 把已观测跳点分摊到有活动证据的工作时间，再平滑 | 对消耗强弱和时段分布的估计 |

近一小时均速以最新读数为终点，从连续记录中寻找相距 45–75 分钟、最接近 60 分钟的那次读数。不按比例拆分半个采样区间，也不会只因时间流逝而改变分母。读数陈旧或间隔不在 55–65 分钟内时标 `*`；连续记录不足时不显示速率。

累计线连接已知采样端点，并不代表已经知道增量在区间内发生的准确时刻。

## 平滑怎样实现

1. 按平台和额度周期分别处理。原始记账保留缺采样、真实中断、账号变化和重置。
2. 用本机任务的开始、结束事件约束工作时间。估计时先压掉已确认的空闲，让相邻工作片段能分摊整数跳点，避免碰巧跳了 1 点就把它全部塞进某个三分钟任务。
3. 在这条“活跃时间轴”上，根据相邻读数分摊增量。工作结束后的短暂上报延迟允许归回刚结束的任务，但只限第一次后续采样，并受最多十分钟采样间隔加一分钟容差约束。
4. 使用升余弦核平滑。目标跨度自适应到约 2–3 次跳点，通常至少 30 个活跃分钟，并受设置中的 60/90/120/150 分钟上限约束。连续估计段的边缘使用镜像，已确认部分的面积归一到观测总量。极长历史在绘制采样变稀时，有效平滑宽度可能扩大。
5. 映射回真实时间。已知开始和结束是硬边界，空闲不会被平滑填满。使用完整可用历史估计，再裁剪成 1h、5h、12h、24h、3d 或 all 视图。

只有额度计数器重置、而本机工作证据连续时，速率可以沿用两侧上下文；原始记账周期仍然分开。尚未收口的尾段会使用逐渐减弱的续估，通常总面积最多一个计数器步长，且不画到最新观测之后。重置前已经触顶的计数器有单独的连续性处理，直到新周期出现增量。任务结束后还需要一次有效后续观测来收口，不能仅凭钟表时间推断。新读数可能修正近期曲线。

停采或其他无法衔接的观测中断后，先合并开头至多三个计数器步长，以降低第一跳的量化相位影响。合并只到最后一个正增量，后面的未跳点观测保留原位置。累计不足三个步长时，尾部沿用一个步长以内的递减形状作为估计，再把头尾一起缩放、平滑到已观测总量；它在重新分配点数，不额外增加预测用量，也不因额度未变而虚构任务结束。这样不会把整段一直压成同一高度，也不会把最后一个跳点全部算到上报的那几分钟。只有一个跳点、且还没有后续观测时，仍只能得到工作时间上的均速；不会为每个任务编造起伏。

这些证据不足的起步曲线保留实线与一位小数悬停数字，不标峰值。递减形状是显示估计，不是已测得的瞬时减速；新读数可能修正它。后续读数到来仍保留开头正增量的合并。这不是限速，大幅实测跳点仍然可见。已确认的缺口也会让左侧仍在工作的估计按最后一次有效采样收口；不代表任务结束，不填补停采区间，也不借用另一侧的消耗。空闲时间仍不参与平滑。

如果本机活动解释不了官方增量，会回退到观测区间估计，不把网页版或其他设备的用量硬算到某个本机 chat 上。

任务边界的数据链路是：本机日志中的生命周期事件 → 完整发布的工作记录 → 活动区间 → 速率估算 → 图表。日志按固定预算分批读取，超长输出行会被跳过，不阻塞后面的结束事件。额度不变本身不代表任务结束；确认结束后，曲线在记录的结束时间截断。

实现见 [ActiveRateEstimator](../src/QuotaWidget.Core/ActiveRateEstimator.cs)、[RateTrend](../src/QuotaWidget.Core/RateTrend.cs)、[TrendContinuity](../src/QuotaWidget.Core/TrendContinuity.cs) 和 [RecentUsageRate](../src/QuotaWidget.Core/RecentUsageRate.cs)。

## 跟真实速率差多少

没有官方瞬时消耗真值，就不能承诺一个经过测量的“准确率百分比”。额度没有跳点时，工作可能仍在持续消耗；一次突发和一段匀速工作，也可能产生相同的采样读数。单靠平滑无法完全区分。

举例：**若计数器按 1 点量化**，仅两端读数的量化就可能给一小时均速带来约 1 点/h 的差异，十分钟窗口则约为 6 点/h。这假设量化方式一致，未包含延迟与缺数据，是量级说明，不是误差保证。Fable 折算后若按 0.5 点跳动，量化尺度相应更细。提高采样频率能减少发现变化的延迟，但不能恢复计数器没有提供的小数精度。

额度与已记录消耗看圆环和顶部累计，近期强度看一小时均速，工作强弱变化看曲线。不要把某分钟的峰值当作精确账单。本机 token 记录用于识别活动与模型；下述 chat 点数是分摊估算，不是精确账单。

## 按 chat 分摊额度

以观测到的周额度增量为总账，用最多八天的本机历史，为每个模型分别拟合非负的 IN / CACHE / OUT 权重；IN 目前包含缓存写入。不把公开 API 价格直接当作订阅扣点规则，速度档位、上下文和平台政策都可能改变比例。

校准按实际采样端点组成约一小时区间，不跨缺口、重置和计数器封顶。至少需要八个有用量的区间（模型较多时每个模型平均四个）及十二点观测消耗。把时间分成三段，轮流保留一段用于验证；另用十二种分量/模型顺序及正则化组合检查分摊是否依赖任意解。平均验证误差不能超过 max(0.8 点，平均每小时观测量的 25%)，单个验证区间误差不能超过 max(2 点，该区间观测量的 50% + 1 点)。这些是接受条件，不是统计置信区间。

在所选范围每一段连续有效观测内，用校准权重按 chat / 模型的 token 比例分配总点数。已确认子代理沿用 token 表的父 chat 归属。未取整的分摊总和等于观测总量；显示一位小数后可能有尾差。至少需要三点及 45 分钟观测。补读未完成、记录冲突、超过八天校准范围、预测不符，或不同权重下某行分摊差异大于 max(0.75 点，该行点数的 30%)，均显示横线，未知不算零。

这个方法假设相关消耗已被本机日志覆盖。与本机活动同步的异地用量仍可能通过验证；账号级验证误差也不代表单 chat 的精度。切到一半的采样区间、尚未观测到的消耗不分摊。校准仅在详情打开或刷新时后台执行，不请求平台额度；token 列保留原范围的原始统计。

精简模式的 Fable 显示近一小时实测均速：已知套餐换算时使用 Claude 周额度点，否则使用 Fable 自身单位。为零、陈旧、覆盖不足，或所有明确识别的 Fable 工作均已结束时隐藏；Opus 继续工作不会延长 Fable。历史点数不删除，缺少结束记录时不虚构超时边界。

## 只用 Fable 时为什么可以共线

支持的套餐会把 Fable 折合到 Claude 周额度单位。某片段的本机模型证据仅有 Fable、且计数器差异在合并量化容差内时，速率图共用 Fable 折合线。

累计图需要额外考虑先前消耗的基准。早先用过其他模型，即使后来只用 Fable，两条累计值仍包含不同的历史；直接隐藏后半段 Claude 会把一条完整曲线挖成零碎短线。因此累计图仅在整个所选记录范围都有 Fable-only 证据、覆盖相符且累计差异不超过量化容差时共线。含混用、未知归属或无法解释的差额时，两条累计线都完整保留。

零增量平台可以延续相邻的已确认 Fable 证据，真实重置和缺口仍不跨越。手动隐藏 Fable 后恢复 Claude 线。顶部累计和存储记录始终各自保留，所以共线时顶部点数仍可能不同；这表示该范围的 Fable 累计，不是修正后的 Claude 账单。
